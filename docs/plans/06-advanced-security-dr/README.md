## 06.01 建立安全验证范围和统一身份

### 06.01.01 建立授权实验与恢复边界

实施内容：列出允许测试的 Namespace、VM、数据和时间窗口，划清管理面、存储和家庭网络的禁止操作范围。

过程安排：为每个故障和安全实验准备停止条件、负责人和恢复材料，先做轻量验证再扩大影响。

完成判定：所有测试有明确授权和回退路径，不对未知设备或公网第三方进行故障注入。

### 06.01.02 部署 Keycloak 与 OIDC 集成

实施内容：使用 keycloak.k8s.internal.egon.top 建立平台用户、团队和客户端，接入 GitLab、Jenkins、Argo CD、Grafana、Backstage 的适用身份接口。

过程安排：核对每个产品版本与许可支持的集成方式，验证回调地址、CA、Token 受众和登出；保留受控本地紧急账户。

完成判定：统一登录正常，但 Keycloak 停止时管理员仍能执行恢复。

### 06.01.03 为 Kubernetes API 建立 OIDC 授权

实施内容：将身份认证与 RBAC 授权分开，为普通开发、团队管理员和平台运维建立映射。

过程安排：使用允许和拒绝操作验证命名空间范围，不因用户能登录门户就授予集群管理员权限。

完成判定：身份到权限的映射可追踪，跨团队越权操作被拒绝并可审计。

### 06.01.04 轮换 ServiceAccount 和机器人凭据

实施内容：检查应用、CI、Operator、仓库和 IaC 使用的身份，淘汰不必要的长期 Token。

过程安排：设置适当的投影令牌、受众、权限与轮换，取消无需 API 的应用自动挂载；验证过期后的报错与恢复。

完成判定：权限收敛不会中断正常业务，所有长期凭据都有明确用途和轮换责任。

## 06.02 落实 Pod 安全与准入策略

### 06.02.01 实施 Pod Security Admission 基线

实施内容：普通业务优先使用 Restricted 目标，先在样例空间执行 Audit/Warn，再逐步强制。

过程安排：CNI、CSI、安全探针等有特殊权限的组件建立精确例外；不因一个系统组件需要权限而放宽所有应用。

完成判定：普通业务不能随意使用特权、宿主路径或敏感主机命名空间。

### 06.02.02 验证 SecurityContext、Seccomp 和 SELinux

实施内容：为样例配置非 root、只读文件系统、Capability 收敛和适用的 Seccomp。

过程安排：在 Rocky Linux 上核对 SELinux、CSI 挂载和编译器行为，记录必要目录权限；安全策略变化逐项验证。

完成判定：应用可运行且权限受限，遇到兼容问题不会直接关闭整台主机安全机制。

### 06.02.03 完善 Kyverno 策略治理

实施内容：实现镜像来源、Digest、签名、资源声明、标签与特权限制；策略版本纳入 GitOps。

过程安排：检查后台扫描和准入场景、Webhook 超时、证书和 fail-open/fail-closed 选择；先用可信与拒绝样例回归。

完成判定：策略真的生效且可解释，控制器自身故障有受控应急流程。

### 06.02.04 演练供应链和准入恢复

实施内容：使用未签名、签名不匹配、被禁止仓库及高风险配置的测试镜像进行拒绝验证。

过程安排：模拟 Harbor 或验证服务不可达，区分策略拒绝与依赖故障；应急放行必须有范围、期限和审计。

完成判定：恢复机制不会变成长期关闭安全准入，正常制品可再次上线。

本节行为核对：[A05](../../reference/official-sources.md#a05)。

## 06.03 管理密钥、审计和工作负载信任

### 06.03.01 使用 SOPS 与 age 管理 GitOps 敏感配置

实施内容：将敏感部署值加密后纳入 Git，设计解密身份、密钥备份与权限分离。

过程安排：验证只有受控交付组件能解密；age 私钥不随加密文件一起提交，恢复材料保存在独立位置。

完成判定：Git 泄漏不会直接暴露所有业务密码，重建集群仍能获得解密能力。

### 06.03.02 部署 External Secrets 与秘密后端对照

实施内容：选择具备实际可用后端的 External Secrets 集成，按需部署 Vault 等实验后端。

过程安排：核对组件许可证、认证、SecretStore 范围和刷新行为；后端不可用时的旧值与失效规则须验证。

完成判定：应用秘密可按策略同步和轮换，Secret 引用不依赖未部署的服务。

### 06.03.03 验证 Vault 解封、备份与故障

实施内容：在隔离实例研究秘密引擎、短期凭据、策略与解封机制，不替换尚未验证的全部基础凭据。

过程安排：备份必要状态和恢复材料，模拟重启及授权拒绝；自动解封存在外部依赖时一并记录。

完成判定：Vault 不成为无法启动平台的隐藏单点，解封密钥没有集中暴露。

### 06.03.04 轮换 Kubernetes 数据加密密钥

实施内容：检查所有 API Server 使用的一致加密配置，设计新旧密钥共存、数据重写与旧密钥退出顺序。

过程安排：先在隔离数据验证读取与恢复，再分步骤操作主集群；保留所需历史备份密钥。

完成判定：新旧数据均可读取，备份不会因为删除旧密钥而永久无法解密。

### 06.03.05 建立 API 与平台审计链路

实施内容：收集 Kubernetes 审计、Git 审查、CI 操作、IaC 变更、网关和身份登录事件。

过程安排：控制审计级别与敏感字段，关联用户、服务账号、提交和实验编号，设置不可随意篡改的归档副本。

完成判定：重要操作能追溯到责任主体，日志本身不泄漏大量 Secret 正文。

### 06.03.06 回访 SPIFFE/SPIRE 与跨服务信任

实施内容：在已具备统一身份和观测后，完善工作负载注册、证书轮换和服务授权。

过程安排：联合信任与网格集成只在适配验证通过后启用；撤销一项注册以确认身份失效行为。

完成判定：人类用户、Kubernetes API 身份与服务间身份职责明确，互不替代。

## 06.04 实验运行时安全

### 06.04.01 部署 Falco 并建立检测基准

实施内容：选择兼容内核与资源预算的 Falco 方案，观察容器进程、文件和系统调用事件。

过程安排：用授权测试应用产生 Shell 启动、敏感目录访问等可控异常；调整告警以减少正常维护的噪声。

完成判定：异常可以触发带上下文告警，必要宿主权限被限制并记录。

### 06.04.02 部署 Tetragon 对照

实施内容：在不同窗口或限定节点启用 Tetragon，研究 eBPF 运行时观测与适用的策略能力。

过程安排：复用 Falco 的安全样例，比较事件细节、内核兼容、开销和噪声，不默认长期同时开启全部探针。

完成判定：得到可比较结果，能够说明观测和阻断各自实际实现范围。

### 06.04.03 将运行时事件接入调查流程

实施内容：把告警关联到 Pod、镜像 Digest、发布版本、服务账号和 Trace/日志。

过程安排：先进行告警加人工调查，再选择受控自动隔离动作；阻断前评估是否影响 DNS、CSI 等基础系统。

完成判定：告警能导向具体处置而非只显示事件数量，误报有恢复方法。

## 06.05 完善 HPA、VPA 与事件扩缩容

### 06.05.01 回访 HPA 多指标与稳定窗口

实施内容：在基础 CPU/内存 HPA 上增加适用的自定义和外部指标，规划最小、最大副本与稳定策略。

过程安排：验证多个指标、缺失数据、指标服务失败与突发流量；普通 HPA 不自动增加底层 ESXi 虚拟机。

完成判定：副本变化符合定义，资源不足的 Pending 可以被识别而非继续无界放大。

### 06.05.02 部署 VPA 并验证资源建议

实施内容：先运行推荐模式，比较建议 Request 与实际负载，确认当前版本更新方式和工作负载支持。

过程安排：在隔离应用测试需要重建或原地调整的行为；避免 VPA 与基于相同 CPU 利用率的 HPA 相互反馈。

完成判定：资源建议有依据，开启自动调整前明确重启、限额和可用性影响。

### 06.05.03 使用 KEDA 扩缩 Kafka 消费者

实施内容：基于已验证 Consumer Lag 创建受控伸缩规则，考虑分区数、认证和消费者重平衡。

过程安排：制造可校验的积压并观察扩容、处理和缩容；限制副本超过有效并行能力造成浪费。

完成判定：积压能够驱动有效吞吐提升，缩容不导致消息处理错误或持续抖动。

### 06.05.04 使用 KEDA 扩缩 RabbitMQ Worker

实施内容：根据队列长度或适用指标设置扩缩容，核对预取、处理耗时和确认策略。

过程安排：模拟消费中断、突发积压与指标不可用，观察副本和消息结果；消费者保持幂等。

完成判定：队列恢复且消息结果正确，不仅看到副本数变大。

### 06.05.05 比较三种缩容到零方式

实施内容：在目标 Kubernetes 实际支持相应 Feature Gate 和指标时，比较原生 HPA、KEDA 与 Knative。

过程安排：分别验证无 Pod 时谁仍提供指标、谁触发唤醒、谁处理冷启动请求；不能用不存在的 CPU 样本唤醒服务。

完成判定：缩零与唤醒机制有实际证据，不把不同方案的请求缓冲能力混为一谈。

### 06.05.06 结合 PDB、优先级与伸缩做压力实验

实施内容：让在线服务、队列 Worker 和批处理同时共享有限计算资源。

过程安排：观察调度、扩容上限、PDB 和抢占，控制负载不影响 Ceph；记录需要节点扩容的场景。

完成判定：能够辨别应用副本弹性与基础设施容量限制，形成优先级和配额建议。

本节行为核对：[A04](../../reference/official-sources.md#a04)。

## 06.06 建设 Knative 与 Serverless 实验

### 06.06.01 部署 Knative Serving 基础

实施内容：核对 Serving、网络插件、Gateway/Ingress 适配与证书方案，使用独立测试域和命名空间。

过程安排：避免与现有 Envoy/Istio 无意叠加多层网关；先验证一次请求、Revision 和内部访问，再开启伸缩。

完成判定：服务可从 internal.egon.top 下的受控内部入口访问，实际使用的网关路径清楚。

### 06.06.02 实验 Revision、灰度与冷启动

实施内容：发布两个 Revision，比较分流、并发、最小副本和缩零后的第一批请求。

过程安排：测量镜像拉取、容器启动、Readiness 和请求等待，不把冷启动耗时全部归因于语言运行时。

完成判定：能够用数据选择是否保留暖实例，冷启动错误和延迟可解释。

### 06.06.03 部署 Knative Eventing

实施内容：在选定兼容版本中建立事件入口、Broker、Trigger 和消费者，规划认证与过滤。

过程安排：验证事件格式、重试、失败目的地和后端依赖；使用已部署消息系统的适配必须先核对支持情况。

完成判定：事件可路由到正确消费者，失败事件有去向而非静默丢失。

### 06.06.04 比较常驻与 Serverless 模式

实施内容：以同一服务对比 Deployment、Knative 和事件 Worker 的资源、延迟与运维成本。

过程安排：分别测试稳定高流量、间歇调用和长任务，不以单一请求耗时判定优劣。

完成判定：形成适用场景结论，按需模块能够退出且不残留路由。

本节行为核对：[A06](../../reference/official-sources.md#a06)。

## 06.07 建设 Dapr 与多语言事件应用

## 06.08 建设 Argo Workflows、Events 与批处理

### 06.08.02 部署 Argo Events 触发链路

### 06.08.03 比较 Workflow、Tekton 与应用 CI

完成判定：形成选择记录，所有实验执行器有资源配额和清理机制。

### 06.08.04 部署 Kueue 队列准入

过程安排：将批处理排队与 kube-scheduler 实际放置分开理解；核对当前 Job/训练工作负载的集成支持。

完成判定：资源不足时任务按规则等待，不把大量已启动 Pod 挤入节点制造压力。

## 06.09 建立第二集群与 Cluster API

### 06.09.01 核算临时集群资源与地址

实施内容：在停用部分大型模块后，为临时集群规划 VM、节点 IP、Pod 10.245.0.0/16 与 Service 10.96.0.0/16。

过程安排：检查与 VPN、主集群和路由重叠，预留 API 与内部域；地址启用前重复 DHCP 检查。

完成判定：临时集群不会挤占主集群最低资源和存储恢复空间。

### 06.09.02 部署 CAPI 管理组件与 CAPV

实施内容：在明确的管理集群部署 Cluster API 与 vSphere Provider，核对 vCenter、模板和 Provider 兼容性。

过程安排：管理对象仅限新建实验集群，不接管现有手工 kubeadm 主集群；API 凭据限定在实验资源池。

完成判定：CAPI 的管理面和工作负载集群职责清晰，主集群资产不会被误纳入销毁。

### 06.09.03 声明并创建实验集群

实施内容：建立所需的 Cluster、控制平面和 Machine 模板，使用与目标 Kubernetes 匹配的 VM 模板。

过程安排：观察从 VM 创建、引导、网络到 Ready 的全过程，定位失败发生在哪一层。

完成判定：得到可访问的小型工作负载集群，创建过程可重复。

### 06.09.04 测试 Machine 扩容、修复与升级

实施内容：在实验集群改变 Worker 数量，核对 MachineHealthCheck 等功能与基础设施实际行为。

过程安排：验证丢失节点、镜像更新和模板变更后的替换过程；节点自动扩缩需要额外控制器与授权，不能只装 CAPI 就声称已经完成。

完成判定：机器生命周期被真实验证，失败资源和孤儿 VM 可以追踪回收。

### 06.09.05 备份管理状态并测试销毁

实施内容：保存管理集群中的 CAPI 状态、凭据与迁移方案，测试主管理面故障的处理边界。
