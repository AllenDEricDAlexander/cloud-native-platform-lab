# 单步骤执行与实验记录模板

本模板在真正执行时复制到 `ops/<阶段目录>/records/<执行批次>/`；实测成功后将稳定操作提炼到 `ops/<阶段目录>/README.md`。保持原步骤编号；同一步骤可有多次执行记录。以下是需要填写的内容说明，不代表已执行。

## 1. 执行上下文

### 1.1 对应步骤与本次目标

记录阶段编号、步骤编号、原文档链接、本次要验证的能力以及与前次执行的差异。只对本次实际目标作结论，不用安装成功代表所有功能通过。

### 1.2 环境与前置检查

记录主机、物理宿主机、命名空间、域名、网段、镜像、软件版本与资源预算。列出已经通过的前置检查、尚未解决的阻塞和会受影响的服务。

### 1.3 风险、备份与停止条件

记录可能被修改的对象、数据、端口和权限，以及备份位置、恢复负责人和中止阈值。备份路径中不暴露密码、Token、私钥或明文敏感数据。

## 2. 实际实施过程

### 2.1 本次采用的参数与文件

记录真正使用的配置值和文件路径，关联 Git 提交。执行阶段再补充实际命令、配置和必要界面操作；涉及秘密时使用安全引用或脱敏值。

### 2.2 按发生顺序保存执行记录

记录实际动作、时间、观察到的状态和关键输出。不把计划内容直接复制为执行证据，失败尝试与调整也保留。

### 2.3 故障与修正

描述故障现象、定位证据、根因判断和采取的修正。对尚未证实的猜测明确标记，避免将一次偶然恢复视作找到根因。

## 3. 验证与恢复

### 3.1 对照完成判定

逐项检查原步骤的完成判定，保存请求结果、对象状态、日志、指标或数据校验。区分正常功能、异常处理、数据一致性和性能四个维度。

### 3.2 清理与回退

记录测试资源如何清理、临时权限如何撤销、网络与故障规则是否恢复、持久数据如何保留。确认没有孤儿磁盘、VIP、公网记录和长期调试入口。

### 3.3 时间与数据结果

需要时记录检测、响应、服务恢复、数据校验的时刻以及丢失/重复数据量。RTO/RPO 和性能结论仅引用本次测量，不编造未测的数值。

## 4. 结论和文档更新

### 4.1 本次状态

在未开始、进行中、已通过、失败待修复、前置条件阻塞、按需未启用中选择实际状态。前置未满足与测试失败是不同情况，不应混记。

### 4.2 可复用结果

将最终配置、脚本、测试用例与恢复动作归入项目适当目录，注明版本和适用条件。随后更新架构台账与阶段状态，但不擅自重排既有步骤编号。
