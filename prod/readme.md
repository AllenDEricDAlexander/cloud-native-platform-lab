# 生产级云原生平台建设方案

## 第一章 overview

本方案以三台物理服务器、ESXi 虚拟化平台和现有网络设备为基础，从零建设生产级云原生平台，覆盖资源分配、基础服务、Kubernetes、持久存储、应用交付、安全、可观测性与灾难恢复。

建设起点为干净的虚拟化环境。平台虚拟机、操作系统模板、Kubernetes 集群和配套服务均按本方案新建，文中的节点规格、服务地址和部署位置为本次建设的目标配置。

### 2. 最终目标

建设一套能够持续承载业务、自动交付应用、定位运行故障并从备份恢复的生产级平台。以明确的资源预算、故障域划分、权限边界和验收标准支撑建设与运维。

关键服务跨物理宿主机部署副本，并通过反亲和、拓扑分布和资源预留约束调度。单宿主机故障时的关键业务承载能力、恢复顺序和资源需求在投产验收中验证。

**存储规划**

- 物理存储预算以 HDD RAID5 的 12 TB、8 TB、8 TB 为基础，分别划分系统、运行时、业务数据和备份空间；SSD 单独安排用途。
- Kubernetes 节点系统盘和 containerd 运行时盘分离，起步各 100 GiB；Ceph OSD 使用单独的数据盘，保留物理盘、阵列、宿主机和虚拟磁盘的映射关系。
- 使用 cephadm 管理 Ceph，通过 Rook External / CSI 向 Kubernetes 提供 RBD、CephFS，并按业务需求提供 RGW 对象存储。副本按三个物理宿主机故障域分布。
- 持久化容量按 OSD 分配、三副本、恢复空间及业务增长共同核算；三副本名义数据容量为 OSD 总容量的三分之一，再扣除必要预留。28 TB 是底层 RAID5 容量，虚拟机磁盘和备份空间也占用该预算。
- 独立备份覆盖基础服务、etcd、Ceph 及业务数据，按业务确定保留周期、RPO 和 RTO，并通过恢复演练验收。

#### 2.2 实现目标

1. **稳定的计算与集群底座**：统一 Rocky Linux、containerd 和 kubeadm 配置，建立三控制平面与 kube-vip API 入口，验证节点维护、控制平面故障与集群恢复。
2. **受控的网络与统一入口**：使用 Cilium 提供 Pod 网络与网络策略，MetalLB 提供业务 VIP，Envoy Gateway / Gateway API 提供 HTTPS、gRPC、证书和路由管理；管理入口限定来源与权限。
3. **可靠的持久化与数据服务**：以 Ceph 和 CSI 提供卷供应、扩容、快照与数据恢复，按业务部署数据库和消息服务，并验证副本切换与备份恢复。
4. **可追溯的应用交付**：通过 CI、Harbor / Nexus、GitOps 完成构建、扫描、签名、发布与回退；发布绑定不可变制品，变更具备审批与审计记录。
5. **完整的运行观测**：统一指标、日志、追踪和告警，建立业务 SLO、容量基线与成本核算，能够定位应用、集群、存储及依赖故障。
6. **持续生效的安全基线**：SELinux 保持 Enforcing，firewalld 持续启用；落实最小权限、网络隔离、证书轮换、凭据保护、镜像准入与操作审计。
7. **可重建的运维体系**：配置、版本、自动化和恢复规程纳入版本管理，关键数据保留独立备份，按计划演练升级、回退和完整重建。

### 3. 阶段目标

阶段按生产部署的依赖与交付顺序划分。00 阶段完成建设准备；01 阶段一并建立 Kubernetes、网络、存储和基础运行保障，交付可承载业务的生产集群。后续阶段在该集群上部署运维平台、数据服务和应用交付体系，完成业务上线并进入持续运维。

安全、监控和备份随各组件部署同步配置。01 阶段具备集群健康监控、基础告警、访问控制、审计和备份恢复能力；02 阶段在此基础上完善集中观测与日常运维。

00 阶段的基础服务部署目标如下，均使用集群外资源，在 01 阶段部署集群前完成交付：

1. **双 DNS 与 NTP 时间服务**：部署内部权威解析、递归解析与第二 DNS，配置节点和管理端的实际解析路径；建立内网时间服务，使节点、基础服务与虚拟化管理时间一致。
2. **内部 CA 与信任分发**：建立内部证书签发和续期流程，为私服及管理服务配置 TLS；向节点、管理端与构建环境分发信任，独立保护 CA 私钥和恢复材料。
3. **Harbor 镜像私服**：部署镜像与 OCI 制品仓库，建立引导镜像、平台组件和业务制品项目；配置镜像同步、版本与摘要锁定、镜像扫描、拉取及推送权限、保留策略和数据备份，使后续集群部署所需镜像可从内网取得。
4. **DNF/RPM 软件私服**：部署 Rocky Linux 系统软件源及平台所需第三方 RPM 的内网供应入口，准备仓库元数据、软件包、签名与校验材料；按目标版本和架构同步软件，配置节点 DNF 仓库与 GPG 校验，保证后续软件安装和更新使用受控内网源。
5. **GitLab 代码私服**：部署代码托管与项目管理服务，配置域名、HTTPS / SSH 访问、用户与项目权限、受保护分支及数据备份，保存平台配置、自动化代码和业务代码，为后续 CI/CD 提供代码入口。
6. **Nexus 依赖与制品私服**：部署业务所需语言依赖的代理、托管及聚合仓库，配置上游、缓存与保留策略、读取及发布权限，并将管理端、构建机和构建环境统一接入内网仓库。
7. **代理、管理与自动化入口**：部署 OpenWrt 显式代理、admin 管理机和 build01 构建客户端，配置内部地址直连、受控出网、管理授权、Ansible 执行环境、版本锁与物料清单，形成可重复执行的节点初始化入口。
8. **备份与恢复服务**：部署备份接收、调度、加密与校验，覆盖 DNS / NTP、CA、Harbor、DNF/RPM 软件源、GitLab、Nexus 及自动化配置；保留独立介质或异机副本，验证从备份恢复基础服务和配置的流程。

00 阶段交付时，节点须通过内部 DNS 和可信 TLS 访问各私服，完成 DNF 安装、Harbor 镜像拉取与容器运行、GitLab 代码拉取与授权推送、Nexus 依赖获取；出网中断后仍能使用已同步物料完成约定的软件安装与构建。基础服务重启恢复、节点基线与身份唯一性、时间同步和备份恢复均纳入交接验收。

01 阶段内部按依赖完成以下部署，并统一验收：

1. **集群与 Pod 网络**：以准备阶段交付的节点为基础，部署高可用控制平面、API VIP、Cilium 和 CoreDNS，完成全部节点入群与基础调度配置。
2. **服务访问与流量入口**：配置 Service 网络、MetalLB 地址池、Gateway、业务 TLS、证书管理与网络访问策略，使集群内外访问路径完整可用。
3. **持久存储接入**：部署主机侧 Ceph、Rook External / CSI、StorageClass、快照及容量策略，使工作负载能够申请、挂载和恢复持久卷。
4. **基础运行保障**：落实 RBAC、工作负载安全约束、审计、资源配额、跨宿主机调度、健康监控、基础告警，以及 etcd / Ceph 配置和持久数据的备份恢复。
5. **集群交付验收**：部署带持久卷的验收应用，通过正式网关与 TLS 访问，验证 Pod 重建后数据保留、控制平面与 VIP 故障切换、存储故障恢复及备份恢复，交付业务命名空间、访问配置和操作规程。

## 第二章 准备阶段

第 3–5.6 使用正式 Shell 完成引导，5.7 从内网 RPM 安装 Ansible / Helm / kubectl，5.8 起由 admin 的 Ansible 编排部署、Shell 完成专用操作。脚本与实际配置随文档交付，不提供 example、自定义 Python 或 Jinja 模板。详细命令、配置、执行位置及逐步验收见 [01 准备阶段部署手册](01-preparation.md)。起点是已安装干净 Rocky Linux 10.2 的 `rocky-base`，先准备模板，再准备 admin，最终交付 18 台 Rocky 与 1 台 OpenWrt。模板不配置免密登录、不包含角色服务或秘密；本章步骤均待人工审查后执行。

01 文档的 Shell、Ansible、配置与静态清单统一放在 [01ops/](01ops/)，admin 上的代码目录为 `/srv/cnpl/configuration/01ops/`。后续 02、03 文档分别使用 `02ops/`、`03ops/`，各自保存配套文件。

OpenWrt 就绪后，管理路径收紧为 **Mac → admin → 其他受管主机**。Ansible、Helm、kubectl、部署密钥和受控配置位于 admin；Mac 的个人密钥只用于 admin。新 Rocky 先用密码修改主机信息，再由 admin 使用 `ssh-copy-id` 配置公钥，验证成功后收紧认证与来源。vSphere 的创建、克隆、加盘、上传与开关机全部由人工通过 Web 控制台完成。

dns、dns02、Harbor、GitLab、Nexus 在各自部署前配置 `192.168.9.10:7890` 显式出网代理，逐台通过 Google HTTPS 验收；内网服务保持直连。主机工具、DNF 与各应用进程分别配置代理，五台服务 VM 的出网授权在私服建成后继续保留。
